# v0.2 架构

LLM 负责提出结构化计划和组织基于证据的语言；本地程序负责检索、验证、确认、模拟事件和状态转换。没有引入多 Agent 或长循环框架。

## 两条运行路径

- `--mode offline`：原有 `agent.py` 规则演示，保留兼容性，不提供自然语言大模型能力。
- `--mode llm`：`natural_agent.py` 为普通问题的主要入口。`llm.py` 提供 `plan` 和 `answer`；旧 `classify` 仅保留兼容。

`plan` 只能返回 `action`、`destination`、`query`。程序验证 action 枚举、地点 ID、字段类型和长度。白名单含知识查询、流程下一步、导航提议、暂停、恢复、取消、状态、求助、澄清和情感陪伴。模型不能输出任意可执行函数或坐标。

医院问答每轮最多两次模型调用：语义规划 → 本地检索 → 基于证据写回复。下一步由流程引擎决定；执行结果由本地模板叙述，不再次交给模型改写。

## 会话与确认

保存最近 12 条消息，包括模拟器送达的进度/完成叙述。每个 Agent 实例绑定一个独立患者场景，不共享会话。

导航和恢复只能先提出请求，产生本地令牌；用户明确确认后消费令牌。令牌 60 秒过期；新意图、故障、取消、求助使旧令牌失效。语义模型返回 confirm 时只提示用户明确确认，不能直接执行。新目标确认后先取消旧任务，取消失败则不启动新任务。

原型支持“等一下，…”等明确前缀先暂停，再处理后半句；复杂自然语言暂停依赖模型，无法保证所有措辞都识别。同步模型请求期间无法处理新输入，因此不能直接用于真实运动控制。

## 知识与生成

`knowledge.py` 将地点、流程和 documents 统一成带 ID/来源的证据。检索为中文双字片段 + 关键词打分，最多取 4 条。支持 `reviewed_at` 和 `expires_on`；过期资料不检索，过期地点不接受导航提议。

生成回答的 `source_ids` 必须来自本轮 evidence。未知引用、缺失引用、格式异常和部分虚假执行宣称会触发资料原文回退。这不是语义蕴含验证，也不能排除模型在引用正确 ID 时编造细节。需要真实语料评估与人工核验。

## 虚拟状态和事件

`SyntheticEnvironment` 组合 Knowledge、WorkflowEngine、PatientState 和 HospitalSimulator。LLM 只读取患者状态，不能写入 registered、checked_in 等事实。

`HospitalSimulator` 沿图的最短边数路径逐 tick 移动。任务有 UUID；事件有独立 UUID。完成事件需匹配当前任务 ID 才更新访问地点；重复事件忽略。不是物理或 ROS 仿真，没有碰撞动力学、行人或真实电梯控制。

`WorkflowEngine` 接受指定事件前检查当前步骤、前置条件和当前位置。到达地点不自动完成报到、接诊或缴费。模拟操作员通过 `/event` 代替医院系统反馈。

## 文件职责

| 文件 | 职责 |
|---|---|
| natural_agent.py | 多轮对话、模型规划、检索回答、事件呈现 |
| policy.py | 结构校验、白名单、确认令牌 |
| llm.py | 模型 HTTP 协议与提示词 |
| knowledge.py | 本地知识加载、来源与检索 |
| simulator.py | 路网、任务、异常、可信模拟事件队列 |
| patient_state.py | 虚拟患者事实 |
| workflow.py | 就诊前置条件与状态推进 |
| synthetic_data.py | 测试表达/多轮场景扩写和真实模型评估 |

部署硬件前还需：模型调用与控制回调分离、并发状态锁、幂等操作、取消确认、真实地图与点位、机器人急停以及可核实的人员联络机制。当前 NaturalAgent 不接收非 MockRobot 类型适配器。
