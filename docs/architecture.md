# 第一阶段架构

核心独立于 ROS 2，直接在 Python 3.10+ 中运行。后续由 ROS 节点接收识别文本并调用 `Agent.respond`，将 `Reply.text` 交给统一 TTS 适配器。

处理优先级：紧急关键词 → 取消/暂停/恢复/状态 → 医疗边界关键词 → 否定/确认 → 地点匹配和规则意图 → 可选模型分类 → 知识查询或任务提议。

`Agent` 为每个会话独立创建，保存当前地点、待确认地点和挂号状态；不持久化原始对话。新问题使旧导航确认失效，挂号追问可保留待确认目标。并发会话不能共享一个 Agent 实例。

模型只返回 intent 与 destination；不返回可执行代码、ROS 话题或坐标。允许的模型意图为 location、route、navigate、flow、comfort、unknown。地点 ID 必须在知识库中。所有模型产生的导航请求也必须再次确认。

`RobotPort.execute` 是同步原型契约。MockRobot 的状态为 idle、running、paused；取消回到 idle。导航成功只表示模拟任务已启动，不表示到达。任务切换先取消旧任务再启动新任务；任一步失败不得报告成功。

## 当前局限

关键词规则不能完整理解任意否定、复杂语义或急症，不能作为真实医疗或运动安全系统。离线导航仅匹配有限表达；模型也可能错误分类，必须通过真实语料评估。急救只产生模拟事件，未联系任何人员。

接真机前必须重新设计异步任务生命周期、超时、幂等 task_id、执行反馈、取消确认、状态锁和独立急停。第一阶段的同步模拟接口不可直接当作生产运动控制器使用。

模型请求目前同步等待，最长 15 秒，会阻塞终端输入；第二阶段必须将模型调用移出 ROS 回调线程，确保停止与求助信号能优先处理。
